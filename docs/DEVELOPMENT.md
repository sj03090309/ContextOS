# 소스 저장 시 설치 앱 자동 반영

이 Mac의 기존 `/Applications/ContextOS.app`을 소스와 함께 업데이트하는 개발용 서비스입니다. 새 버전을 다운로드하는 배포용 자동 업데이트와는 별개입니다.

```sh
python3 scripts/dev_auto_update.py enable
python3 scripts/dev_auto_update.py status
python3 scripts/dev_auto_update.py disable
```

`enable`은 현재 체크아웃 경로를 사용자 LaunchAgent에 등록합니다. 로그인할 때 다시 시작하며, 터미널을 닫아도 감시합니다. 소스 폴더를 옮기면 기존 위치에서 `disable`한 뒤 새 위치에서 다시 `enable`하세요. 다른 설치 위치는 `enable --to "$HOME/Applications/ContextOS.app"`처럼 명시합니다.

체크아웃이 바탕화면 안에 있으면 첫 실행에서 macOS가 Python의 바탕화면 폴더 접근을 요청할 수 있습니다. 허용하기 전에는 감시가 시작되지 않습니다. 자동화 도구 자체인 `dev_auto_update.py`를 수정한 경우에는 `enable`을 다시 실행하여 서비스 코드도 새로 읽게 합니다.

저장 후 약 2초 동안 편집이 없으면 Release 빌드, 기존 위젯 패키징·서명·번들 검증을 진행합니다. 검증이 끝난 뒤 대상 앱만 정상 종료하고 같은 경로에 설치하여 다시 실행합니다. 반영 시간에는 Swift·WidgetKit 빌드 시간이 포함됩니다. SwiftUI 코드를 실행 중에 주입하는 방식은 아닙니다.

- `Sources/`, `NativeWidgets/`, `scripts/`, 라이선스·아이콘·패키지 설정과 번들에 포함되는 문서를 감시합니다. `Tests/`와 일반 문서 편집은 설치 앱을 바꾸지 않습니다.
- `.build/`, `dist/`, Git·인덱스·캐시 출력은 감시하지 않습니다. 연속 저장을 묶고, 빌드 중 소스가 바뀌면 그 후보를 설치하지 않은 채 최신 내용으로 다시 빌드합니다.
- 빌드·서명·검증 실패 시 기존 실행 앱을 유지합니다. 같은 실패를 무한 반복하지 않고 다음 편집에서 재시도합니다. 재실행 실패 시 이전 번들로 복구를 시도하고 오류를 남깁니다.
- 최초 자동 업데이트 전 앱과 가장 최근 이전 앱을 보관합니다. 이 서비스가 만든 중간 백업만 새 앱 실행 확인 후 정리합니다. 기존 수동 설치 백업은 유지합니다.
- 기존 인증서와 승인된 위젯 App Group을 그대로 사용합니다. 현재 `sign_production_widgets.sh`와 일치하는 설치가 필요하며, 키체인에 해당 서명 키가 없으면 업데이트를 중단합니다. 인증서·계정을 새로 만들지 않습니다.
- 설정·인덱스·사용 기록은 삭제하지 않습니다. 정상 종료는 활동 집계를 저장하지만, 실행 중인 수동 작업 타이머는 앱 재시작으로 중단됩니다.
- 이미 연결된 AI의 MCP 프로세스는 계속 실행합니다. 새 MCP 코드는 AI 도구를 재연결하거나 다시 실행한 뒤 적용됩니다. 앱 재실행만으로 기존 MCP 세션의 코드를 교체하지는 않습니다.

`status`는 활성화 상태, 최근 설치 빌드, 오류와 로그 경로를 보여 줍니다. `watcher.log`는 감시·설치 결과, `build.log`는 마지막 시도의 상세 빌드 기록입니다. 소스가 바뀌지 않으면 재빌드하지 않습니다. `disable`은 자동 감시와 로그인 시작을 해제하며 설치 앱·설정·백업을 보존합니다. 설치가 진행 중이면 정상 종료·복구를 마칠 시간을 둡니다.

서비스 등록 없이 한 번 실행하려면 다음 명령을 사용합니다.

```sh
python3 scripts/dev_auto_update.py once
python3 scripts/smoke_dev_auto_update.py
```

기존 `package_app.sh`와 `install_app.sh`의 수동 동작은 유지합니다. 패키징 명령만 실행하면 앱을 설치하거나 종료하지 않습니다.
