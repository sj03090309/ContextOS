# ContextOS 배포 준비 분석 · 2026-11-03

## 판단 기준과 결론

대상은 **개인 개발자가 사용하는 로컬 macOS 메뉴바 앱, Claude Code·Codex MCP 연결, 사용량 대시보드와 WidgetKit 위젯**이다. 이 범위에 필요한 정확성·개인정보 선택·설정 보존·업데이트 복구·실제 실행을 평가했다. 서버, 계정, 원격 텔레메트리, 자동 업데이트, 결제, 다중 조직 권한 체계는 이 제품에 필수인 조건으로 추가하지 않았다. Windows는 기존 문서대로 준비 단계이며 이번 macOS 배포 판정에 완제품으로 포함하지 않는다.

점검 시작 시 소스 테스트만으로는 발견되지 않던 설정 덮어쓰기 경쟁, 원자적으로 교체된 로그의 잘못된 집계, Git 저장소의 명령 실행, 패키징의 설치 경로 침범이 있었다. 이들은 실제 사용에 필요한 수정이다. 수정 후 로컬 빌드·설치와 공개 배포의 신뢰 검증은 계속 구분해야 한다.

**공개 고객 배포의 모든 조건이 갖춰진 상태라고 판정하지 않는다.** 이 Mac에서 사용 가능한 인증서는 Apple Development이며, 기존 설치본의 Gatekeeper 평가는 거부였다. Developer ID Application·공증·staple·Gatekeeper를 통과한 최종 고객 패키지, 배포 권리/이용조건 결정, 선언한 지원 환경의 깨끗한 Mac 시험은 별도 잔여 조건이다. 서명 우회나 임의의 이용조건 추가로 이 조건을 통과 처리하지 않았다.

## 기존 핵심 동작의 평가

- **컨텍스트 선택과 전달:** 관련 파일 계획과 본문 조립은 공통 경로를 사용한다. 필수 보조 구현이 예산에 들어오지 않으면 누락·필요량을 표시하며 완전 전달이나 절감으로 계산하지 않는다. 함수 선택과 관련도는 휴리스틱이므로 임의 저장소의 모든 의미적 의존성을 보장하지 않는다.
- **프로젝트 경계:** descriptor를 따라 no-follow로 읽고 일반 파일·크기 한도·루트 경계를 확인한다. 민감 경로·중첩 ignore·외부 링크 차단을 합성 MCP 시험에서 재확인했다. 소스 파일 안에 하드코딩된 모든 비밀을 탐지하는 제품은 아니다.
- **인덱스 최신성:** 쿼리 시 증분 검사, SQLite 직렬 트랜잭션과 busy timeout, parser revision, 강제 재색인 경로가 있다. 의도적으로 크기와 mtime을 모두 보존한 일반 소스 편집은 메타데이터 검사만으로 발견하지 못할 수 있다. 이 경우 `index_project`가 전체 재파싱 경로다.
- **세션 중복 제거:** bounded/locked/TTL 메모리를 사용하고 `fresh=true`로 본문을 다시 받을 수 있다. 작은 예산, 중복·fresh, 강제 재색인을 실제 stdio MCP로 검증했다.
- **사용량의 정직한 표시:** 누락·부분 수집·지원하지 않는 형식·중지 상태와 관측된 0을 구분한다. 로컬 로그 기반 사용량과 텍스트 크기 추정을 실제 공급자 청구액 절감이나 생산성 증가로 해석하지 않는다.
- **운영 비용:** 기존 이벤트 감시, 닫힌 패널의 느린 갱신, 저전력/열 상태 반영, 잠금·절전 중단을 유지한다. 전체 역사 집계는 동의 후 스트리밍하므로 매우 큰 보관 로그의 첫 집계는 오래 걸릴 수 있다. 이번 검증이 장기간 누수 없음의 증명은 아니다.
- **연결과 복구:** 미리보기/취소 무쓰기, 적용 전 충돌 검사, private 백업, 사용자 키·다른 MCP·승인 하위 테이블 보존을 유지한다. 지원 범위를 벗어난 TOML은 추측해서 재작성하지 않는다. 다중 외부 프로그램 사이의 완전한 원자성이나 전원 손실 내구성은 주장하지 않는다.
- **제품의 로컬 경계:** 자체 서버·LLM 요청·텔레메트리를 추가하지 않았다. 선택된 소스는 사용자가 연결한 AI 에이전트에 전달되고, 그 이후 전송은 해당 도구의 설정을 따른다.

## 공개 배포에 남은 구체적인 조건

1. **실제 고객용 서명/공증:** 기존 Apple Development 서명은 로컬 시험용이다. 소유자가 Developer ID Application과 배포 팀의 App Group·필요한 provisioning을 준비해야 한다. 최종 패키지의 모든 실행 파일을 동일 팀으로 서명하고 Hardened Runtime·secure timestamp·디버깅 권한 해제 후 공증·staple·Gatekeeper를 확인한다. `python3 scripts/verify_bundle.py <app> --distribution`이 이 신뢰 조건을 검사한다. 업로드·계정·인증서·결제를 임의 실행하지 않았다.
2. **실제 지원 범위:** 이 Mac의 Apple Silicon·macOS 27.2 실행과 CI의 빌드 검사는 macOS 14 또는 Intel 고객의 최초 설치 증거를 대신하지 않는다. 실제 확인한 환경으로 첫 배포 범위를 좁히거나, 선언한 환경에서 깨끗한 설치→연결→호출→업데이트→복구를 확인해야 한다.
3. **배포 권리와 연락 경로:** ContextOS 자체 라이선스/바이너리 이용조건, 아이콘·마스코트의 배포 권리, 운영할 지원 연락 경로를 소유자가 결정해야 한다. 의존성 고지는 이미 포함하며, 감사 도중 임의의 소유권·판매 약속을 만들지 않았다. 유료 판매를 선택할 때만 가격·업데이트/환불 범위를 결정하면 된다.
4. **정확한 최종 산출물:** 공증 뒤 staple한 앱으로 ZIP·SHA256을 다시 만들고 실제 배포할 동일 파일을 검증한다. 개발용 패키지, CI 성공, 설치 구성 doctor의 `readyToConnect`를 고객 설치 완료나 실제 에이전트 호출의 증거로 바꾸어 부르지 않는다.

이들은 조직 규모 때문에 필요한 부가 체계가 아니라 이 제품을 처음 받는 사용자의 설치·데이터 선택·복구와 직접 연결되는 조건이다. 그 외 서버화·계정 체계·자동 과금·전 플랫폼 동등 기능을 이번 범위의 배포 필수 조건으로 요구하지 않는다.
