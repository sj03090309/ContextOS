## Codex/dot: missing sources versus duplicates

The collector still reads only bounded, permitted local JSONL sources. Provenance is now taken from explicit session metadata: CLI, desktop originators, editor, SDK/exec, subagent or unknown. It is never inferred from a running app. Explicit nested or string subagent sources are excluded from parent-only accounting even without a fork field, retaining a partial warning. Copied desktop/CLI sessions still deduplicate by canonical identity. Provenance remains app-side metadata, not a new shared-widget payload field.

The actual operating view now identifies its currently observed Codex records as SDK/exec and labels the provider `Codex · 로컬 기록`. It explains that this is not the complete dot/cloud total. Current dot usage could not be established from these local sources. A read-only audit of counter metadata in `state_5.sqlite` found 142 records with latest update **2026-10-13 07:22:47 UTC**, and no current parent thread; the audit was refreshed at **08:47:46 UTC on October 16** (`codex-observable-coverage.json`). No prompt/title/body/credential fields were selected. Lifetime thread totals and a final update timestamp do not establish daily spending, so these totals were **not** added to today's or weekly graph, rankings or project totals. This is a source gap, not evidence of zero usage.

Official [App Server documentation](https://developers.openai.com/codex/app-server/) describes active-thread token usage notifications. No new server attachment, notification subscription, credentials, network collector or collection permission was introduced. Full dot/cloud accounting remains unsupported until a suitable authorized source exists. No restricted session path or permission denial was bypassed. No raw prompts, file contents or keys enter widget sharing.
