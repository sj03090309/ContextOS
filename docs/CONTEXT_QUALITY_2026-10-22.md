# ContextOS 관련 구현 검색·본문 보존 개선

2026-10-22 · 로컬 설치 버전 2.1.0, 빌드 2117.

이 문서는 빌드 2117의 결과다. 이후 작은 예산의 우선 배치와 다른 파일의 의존 구현 추적은 [빌드 2118 개선 보고서](CONTEXT_DEPENDENCIES_2026-10-23.md)에 기록했다.

## 결과

이전에 빠졌던 같은 파일의 보조 함수, 사용한 상수·속성, TypeScript 화살표 함수 본문을 함께 보존하도록 개선했다. 같은 고정 질문 12개에서 기본 8,000 추정 토큰 예산의 핵심 파일 본문 전달은 **8/12 → 12/12**, 250 추정 토큰의 정보 보존 검사는 **1/4 → 4/4**로 개선됐다.

비교 기준은 이미 백그라운드·검색 성능을 최적화한 **빌드 2116의 작업 소스**다. 이번 개선 후 500파일의 인덱스 확인·검색·본문 조립 중앙값은 **319.186ms → 273.221ms**였다. 이전 최초 진단의 더 느린 버전을 비교 기준으로 삼지 않았다.

## 무엇을 바꿨는가

- 복합 식별자 전체가 일치하는 구현·파일에 가산점을 준다. 질문에 구현 이름이 명시됐는데 관련 단어가 많은 테스트 파일이 먼저 나오는 경우를 줄였다. 테스트를 요청하면 일반 테스트 감점을 적용하지 않으며, 명시한 파일 경로는 계속 우선한다.
- 한국어 `컨텍스트`, `문맥`, `요약`, `예산`, `본문`, `슬라이싱`을 일반적인 대응 용어로 확장한다. 특정 평가 질문의 답 경로를 하드코딩하지 않았다.
- 선언 패턴과 공통 어휘 스캔을 함께 사용해 TypeScript/JavaScript의 const·let·var 화살표 함수, async·generic 화살표 함수, 함수 표현식, 클래스 화살표 속성과 메서드를 인식한다. 여러 줄 초기화식과 객체 반환형도 범위를 보존한다.
- 슬라이싱할 때 함수가 실제 코드에서 참조한 같은 파일의 함수·메서드와 모듈/타입 상수·속성을 따라간다. 순환 참조는 방문 집합으로 종료한다. 같은 이름의 메서드는 가능한 경우 현재 타입의 것을 우선한다.
- 주석·일반 문자열 내용은 참조 검색에서 제외한다. Swift 문자열 보간, JavaScript 템플릿 보간, Python f-string 안의 실제 표현식은 참조에 포함한다. 문자열·정규식의 중괄호가 함수 경계를 닫는 문제도 방지한다.
- 타입 이름과 구체적인 메서드를 함께 요청하면 타입 전체의 무관한 메서드를 함께 넣지 않는다. 타입 자체를 요청하면 실제 구현을 보존하면서 빈 줄·주석만 있는 채움 구간을 줄인다. 여러 줄 문자열은 그대로 보존한다.
- 범위를 확정하지 못하거나 문자열 등이 닫히지 않은 소스는 전체 원문을 사용하는 보수적인 경로로 돌아간다. 최종 응답의 예산 제한은 그대로 적용한다.
- 파서 개정 정보를 인덱스 트랜잭션에 저장한다. 기존 파일의 크기·수정 시각이 같아도 업그레이드 후 한 번 다시 파싱하고, 이후에는 기존 증분 확인 경로를 사용한다.
- MCP 파일 계획의 `Read ONLY` 문구를 추천 시작 파일로 바꿨다. 전체 파일이 남은 예산보다 큰 후보도 별도로 표시하며, 슬라이싱 본문을 받는 도구를 안내한다.

공통 스캔은 파일을 읽을 때만 일시적으로 생성한다. 괄호 짝은 한 번 계산해 재사용하고, 파싱과 슬라이싱이 같은 스캔 결과를 공유한다. 대부분의 함수를 이미 선택한 넓은 질문은 의존성 지도를 만들기 전에 전체 소스로 돌아간다. 추가 모델 호출·외부 라이브러리·상시 감시 작업은 없다.

## 같은 입력으로 측정한 품질

최초 진단과 같은 `bf42f28`의 git archive 사본을 사용했다. 최근 편집 신호가 없는 고정 소스이며, 12개 질문·필요한 핵심 파일·4개 정보 보존 소스·성공 조건을 바꾸지 않았다. 각 바이너리가 자기 파서로 강제 인덱싱한 뒤 실제 stdio MCP를 호출해 버전 간 인덱스 혼입을 피했다. 실제 계정·대화 기록·분석 저장소·네트워크에 접근하지 않는 임시 홈에서 실행했다.

| 측정 | 기존 4,000 | 개선 4,000 | 기존 8,000 | 개선 8,000 |
|---|---:|---:|---:|---:|
| 계획의 첫 파일이 핵심 파일 | 4/12 | 7/12 | 5/12 | 10/12 |

| 실제 본문 응답에 핵심 파일 | 5/12 | 9/12 | 8/12 | 12/12 |
| 질문 응답의 로컬 추정 예산 준수 | 12/12 | 12/12 | 12/12 | 12/12 |

| 별도 250 추정 토큰 검사 | 기존 | 개선 |
|---|---|---|
| Python 요청 함수 본문 | 보존 | 보존 |
| 같은 파일의 서명 검증 보조 함수 | 누락 | 보존 |

## 성능을 유지했는가

같은 Mac의 Release 빌드로 합성 Swift 파일 500개, 함수 12,000개, 소스 1,985,720bytes를 사용했다. 버전별 별도 프로세스를 7회씩 실행하고 순서를 교차했다. 각 프로세스 안의 반복 측정 중앙값을 다시 중앙값으로 비교했다. 다른 앱은 종료하지 않았고 OS 캐시·시스템 부하를 고정하지 않았다. 변동이 있는 초기 실행도 모두 결과에 포함했다.

| 측정 | 이미 최적화된 기존 버전 | 이번 개선 |
|---|---:|---:|
| 최초 인덱싱 | 288.467ms | 263.205ms |
| 변경 없는 인덱스 확인 | 15.622ms | 15.803ms |
| 검색 순위 계산 | 38.158ms | 38.185ms |
| 인덱스 확인·검색·본문 조립 전체 | 319.186ms | 273.221ms |
| 최대 RSS 중앙값 | 25.313MiB | 25.234MiB |

전체 처리 시간은 약 **14.4% 감소**했고, 순위 계산과 메모리는 비슷한 수준이었다. 성능용 입력은 14회 모두 선택 파일 7개·본문 7,994 추정 토큰이며 결과 해시가 `3e9c09c35c92b5a62b460bb4b2cfca7236fec8b719704cf98007434369555922`로 같았다. 품질용 입력은 누락을 수정했으므로 출력이 달라진다.

이미 적용한 숨김 상태 30초/저전력 60초 집계, 잠금·잠자기 중 갱신 중단, 중복 작업 합치기, 활동 로그 읽기 제한과 세션 기억 상한은 유지한다. 이번 실험은 장시간 배터리 소모량을 직접 측정한 결과는 아니다.

## 검증·설치

- macOS 전체 테스트: **414개 통과**, Windows 전용 3개 건너뜀.
- 이식용 준비 프로필: **15개 통과**, 해당 환경의 미지원 경로 5개 건너뜀.
- 요청 본문, 보조 함수·전역 값의 전이 참조, 순환, 동일 메서드명 분리, 주석·문자열의 가짜 참조, 문자열 보간, 여러 화살표 문법, 여러 줄 Python 선언, 객체 반환형, 기존 인덱스의 1회 자동 갱신을 회귀 검사했다.
- 기존 실제 MCP 검사: 예산 1·30·100·250·500, 중복 전달 제거·fresh, 강제 인덱싱, 민감 파일·링크·프로젝트 경계·잘못된 요청 이후 복구 통과.
- 기존 팀·App Group·위젯을 유지해 빌드 2117을 만들고 서명을 검증했다. `<local-app-bundle>`에 설치한 호스트·CLI·MCP·위젯의 네 실행 파일이 검증 패키지와 같은지 확인했다.
- 설치 후 실제 대시보드·AI 사용량·개발 시간 화면을 열었다. 개인 정보 숨기기와 기존 개발 활동 설정·누적 기록이 유지됐다. 기존의 일부 집계 불가/VS Code 확장 신호 필요 상태도 그대로 표시한다.
- 직전 빌드 2116은 `<local-backup-app>`에 복구용으로 보존한다. 이미 실행 중인 Codex/Claude의 MCP 프로세스에는 이전 코드가 남을 수 있으므로 AI 도구 재시작 후 새 바이너리를 사용한다.
- 확인을 마친 뒤 이번 작업의 재생성 가능한 빌드·캐시·임시 검사 파일 13,731개, 논리 크기 약 1.36GB를 삭제했다. 검증한 앱·소스·테스트·보고서·인덱스·설정·사용 기록·복구용 앱은 보존했고, 창을 닫은 뒤 새 앱이 메뉴바에서 계속 실행 중임을 확인했다. 삭제 범위는 로컬 전용 `cleanup.json`에 기록했다.

재실행 도구는 `scripts/audit_context_quality.py`, `scripts/benchmark_context.py`, `contextos-bench`다. [요약 수치](benchmarks/context-quality-20261022/summary.json)와 합성 입력의 질문별 결과·성능 측정·소스 해시는 [공개 검증 자료](benchmarks/context-quality-20261022/)에 있다. 실행 로그·설치·정리 원자료는 로컬 전용이며 저장소에서 제외한다. 공개 범위는 [검증 자료 안내](benchmarks/README.md)를 따른다.

## 남는 한계

4,000 예산에서는 큰 파일 3개의 본문이 여전히 들어가지 않으며, 8,000에서도 계획의 첫 파일이 핵심 파일인 경우는 10/12다. 계획의 전체 파일 비용 추정과 실제 슬라이싱 비용의 차이가 남아 있다. 관련 파일을 더 읽을 여지를 남기는 안내 문구로 이 한계를 드러냈다.

이 구현은 언어 전체를 해석하는 AST·타입 검사기가 아니다. 동적 호출, 복잡한 별칭·매크로, 모든 언어 문법과 스코프를 완전히 해결하지 않는다. 새 보조 함수 추적의 범위는 같은 파일이며, 다른 파일은 기존 import 그래프 확장과 예산에 의존한다. 의존 구현이 크면 예산에 맞춰 생략될 수도 있으므로 작은 예산에서 모든 의존성을 항상 전달한다고 보장하지 않는다.
