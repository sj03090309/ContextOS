# 위젯 점검 및 반영 결과 — 2026-10-24

ContextOS 2.1.0 빌드 **2120**을 `/Applications/ContextOS.app`에 설치하고 실행했다.

## 확인 및 수정

- 수동 새로고침·작은 위젯 항목 변경 후 파일만 저장하고, 위젯 화면 갱신 요청은 15분 제한에 막히는 문제를 수정했다.
- 뭉치 표시 설정을 위젯에 전달하는 구독을 추가했다. Combine이 속성 변경 전에 보내는 새 값을 명시적으로 전달한다.
- 날짜·시간대 변경, 초기 집계 완료, 수집 상태와 타이머 상태 변경은 일반 갱신 제한을 기다리지 않는다. 일반 카운터는 기존의 분당 저장·15분 갱신 요청을 유지한다.
- 저장 실패 시 갱신을 요청하지 않고 기존 데이터를 유지한다. 빈 시작 화면과 샘플 데이터가 실제 집계를 덮어쓰지 않는 조건도 검증했다.
- macOS의 위젯 서비스가 삭제된 Desktop 앱 경로를 참조해 새 위젯 실행에 실패하는 것을 확인했다. 위젯 서비스 `chronod`를 재시작해 현재 설치 경로로 복구했다. 위젯 배치·사용 기록은 삭제하지 않았다.

## 검증

- 전체 테스트: 446개 통과, 다른 플랫폼 전용 3개 제외. 위젯 회귀 테스트 8개 포함.
- Release 앱 및 소형·중형·대형 WidgetKit 확장 빌드 성공. 기존 팀 서명, 기존 App Group, 확장의 sandbox 권한을 검증했다.
- 설치된 앱·CLI·MCP·위젯 실행 파일 4개의 SHA-256이 검증한 패키지와 모두 일치했다.
- 실제 UI에서 뭉치 표시를 껐다 켜고, 작은 위젯 항목을 작업 타이머로 바꿨다가 오늘 토큰으로 복원했다. 새 값이 공유 파일에 즉시 저장되고 실제 WidgetKit 갱신이 실행됨을 확인했다.
- 수동 새로고침 직후 앱과 공유 파일의 집계가 정확히 일치했다. 세 크기의 실제 타임라인 요청도 동일한 공유 집계 시각을 읽었다. 실제 토큰 수와 계측 시각은 로컬 전용 검증 자료에 보관한다.
- macOS가 생성·저장한 세 크기의 최신 `.chrono-timeline` 화면 데이터에 모두 **15.37M**이 들어 있는 것도 확인했다.
- 설치된 MCP의 도구 6개와 실제 `project_stats` 호출이 정상 동작했다.

## 검증 범위와 복구

화면 자동화는 닫힌 알림 센터의 placeholder 창을 반환해 전경 위젯의 숫자를 직접 읽는 최종 화면 확인에는 제한이 있었다. 실제 WidgetKit 프로세스·타임라인 로그와 macOS가 생성한 최신 화면 데이터를 대조해 반영을 검증했다. 물리적인 화면 표시 시각은 [WidgetKit의 시스템 갱신 정책](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)을 따른다.

상세 로그·해시·검증 JSON은 로컬 전용 `.audit/` 기록에 보관한다. 실제 사용량과 기기별 설치·UI 원자료는 저장소에 포함하지 않는다. 공개 범위는 [검증 자료 안내](benchmarks/README.md)를 따른다.

이전 앱은 `<local-backup-app>`에 복구용으로 보존했다. 기존 작업과 사용 기록, 연결 권한은 유지했다.
