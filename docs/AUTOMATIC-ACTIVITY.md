# 자동 상태 표시줄 활동 시간 후보
2026-10-14. 6f9e183의 직접 타이머 중심 후보를 바꾸는 구현이다. 설치/권한/운영 앱 교체는 하지 않았다.

## 기본 UX
VS Code 아래 상태 표시줄에 `◷ 01:23:45 · 활동 추정`을 표시한다. 시작 버튼이나 공백 확인 질문은 없다. 확장 enabled와 host receiver enabled를 명시적으로 켠 설정은 사용자 환경설정에 저장하며 재시작 때 연결만 자동 복원한다. 처음 설치/연결에 동의한 뒤에는 포커스·이벤트에 따라 자동으로 시작·정지한다. 앱 화면은 같은 오늘 집계 하나를 크게 표시하며 직접 타이머/전경 체류는 접힌 별도 도구이다. 작은 위젯 선택의 기본 후보도 `오늘 활동 · 추정`이다. 기존 사용자가 선택한 항목은 유지한다. 중간/큰 토큰 위젯 정보 밀도는 늘리지 않았다.

## 시간 기준 — 제품 가정이며 정확한 코딩 실측 아님
- 중앙 macOS 프로세스의 단조 시계 수신 시점을 쓴다. 포커스 획득 또는 포커스된 창의 편집·커서/선택·스크롤 콜백 이후 **최대 5분**을 활동으로 분류한다. 이 5분은 제품 가정이며 읽기/생각의 실제 종료 시각을 뜻하지 않는다. 포커스만으로도 첫 5분이 분류될 수 있어 방치가 포함될 수 있다.
- 5분 동안 해당 사건이 없으면 질문 없이 자동 일시정지한다. 새 사건이 오면 그 시점부터 자동 재개하고 이전 공백을 채우지 않는다. 읽기/생각만 하며 움직이지 않는 5분 이후는 빠질 수 있다. AI/프로그램 편집·커서 이동과 사람의 동작도 구분하지 못한다. 터미널·웹·다른 앱의 개발 활동은 이 후보의 범위 밖이다.
- 콜백 횟수는 실제 관측값이고 `활동 추정 시간`과 별개이다. 내용 변경 배열 길이만 확인하며 배열 원문·document·URI·선택 위치·스크롤 범위·제목·키 입력·언어·프로젝트는 읽지 않는다. selection/visible-range 콜백은 인자를 아예 사용하지 않는다.
- 최대 4개 로컬 editor host 연결을 받아 중앙에서 한 구간만 합산한다. 마지막 포커스 창이 우선이며 오래된 창의 blur는 새 창의 집계를 중단시키지 않는다. nonce/sequence로 재생을 무시한다. 5번째 연결은 받지 않는다.
- 30초 heartbeat는 연결 상태만 유지하며 5분 활동 창을 연장하지 않는다. 45초 동안 수신이 없으면 연결 불확실로 자동 정지하고 누락 표시한다. 프로토콜 누락/실패 구간을 거꾸로 복원하지 않는다.
- 수신된 절전/세션 비활성 알림, 2초 이상 벽시계와 단조 시계 불일치, 단조 시계 역전은 미완료 구간을 버리고 일시정지한다. 수신기는 유지하며 새 포커스/활동 사건으로만 자동 재개한다. 자정/시간대 변경에서는 새 일자의 미관측 값으로 시작하며 경계를 넘은 마지막 checkpoint 일부가 빠질 수 있어 partial로 표시한다. DST의 시각 반복은 단조 경과 시간으로 센다.

## 하나의 집계와 저장
중앙 앱이 집계한 `EstimatedActivitySnapshot`을 상태 표시줄에 회신하고 앱/위젯에도 넣는다. 클라이언트는 1초 타이머나 Date 보간으로 값을 늘리지 않는다. 활성일 때 중앙에 1개 1초 checkpoint/broadcast 타이머가 있으며 일시정지하면 해제한다. extension은 사건을 250ms로 병합하고 30초 연결 heartbeat만 유지한다. 원시 이벤트 스트림은 디스크에 쓰지 않는다.

오늘의 **추정 집계와 규칙/시간대/일자/시각/partial만** `~/Library/Application Support/ContextOS Observation Candidate/activity-day-v1.json`에 저장하는 후보이다. 16 KiB 상한, 디렉터리 0700/파일 0600. 평상시 최대 60초 간격 및 상태 경계에서 원자 저장한다. 재시작하면 같은 일자/시간대의 저장된 합계만 복원하고 paused/partial로 시작한다. 열린 구간·마지막 이벤트·nonce·창 ID는 저장/복원하지 않는다. 크래시 이전 최대 60초 정도가 빠질 수 있으며 공백을 추정해 복구하지 않는다. 다른 일자/시간대는 합치지 않으며 다일 이력은 제공하지 않는다. 중지/확장 제거 후 파일의 자동 만료·삭제는 없으며 사용자가 삭제할 때까지 마지막 집계가 남을 수 있다.

위젯은 같은 중앙 집계의 **마지막 저장 값**이다. 일반 공유 저장은 60초, 상태 변화는 별도 반영, WidgetKit reload는 기존 15분 제한을 유지한다. OS가 표시 갱신을 지연할 수 있으므로 상태 표시줄과 동시 실시간 값이라고 하지 않는다. 90초 지난 활동 집계는 이전 집계로 표시하는 timeline도 준비한다.

## 설치 승인 범위 변경
아직 승인/설치/활성화하지 않았다. 로컬 VSIX v0.2.0은 편집 콜백 외 **커서/선택·visible-range 사건 종류**를 추가하고, 같은 Unix socket으로 **오늘 집계를 회신**하며, 오늘 추정 집계 파일을 추가하는 변경이다. 이 변경까지 설명한 뒤 설치/연결 승인이 필요하다. 외부 전송·TCP·텔레메트리·스크린샷·키 내용·파일 내용·API키 수집은 없다. Accessibility/Input Monitoring·Apple 자격증명·결제도 요구하지 않는다. 같은 UID의 다른 프로그램이 패킷을 흉내 낼 수 있으며 확장 서명 출처 인증은 아니다.

공식 API 근거: [VS Code window API](https://code.visualstudio.com/api/references/vscode-api#window)의 createStatusBarItem, onDidChangeWindowState, onDidChangeTextEditorSelection, onDidChangeTextEditorVisibleRanges 및 workspace.onDidChangeTextDocument. 이벤트가 사람이 작업한 시간이라는 보장은 제공하지 않으므로 제품 추정 규칙을 별도로 명시한다.

잠금 감지는 OS 세션/절전 알림과 확장 focus 전달에 의존하며 실제 잠금 전환은 아직 확인하지 않았다. 실제 VS Code Extension Host/설치/상태 표시줄/새 앱 GUI는 미검증이다. 이전 CUA 접근은 timeout이었으며 잠금 해제 확인이 없다. 합성 단위검사와 렌더 증거는 실제 사용자 화면과 구분한다.
