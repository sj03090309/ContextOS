# 토큰 수집 경고 수정과 context 실사용 검증

2026-10-23 · ContextOS 2.1.0, 빌드 2119 · 현재 Mac의 로컬 사용 범위.

## 수정 결과

데스크톱에 설치한 새 앱의 실제 화면에서 **오늘 관측 토큰: 로컬 기록 집계**, **Codex: 수집됨**, **Claude Code: 기록 없음**을 확인했다. 사용량이 없는 경우를 관측된 0으로 만들지 않는다.

경고에는 여러 원인이 겹쳐 있었다.

- 최근 7일을 표시하면서 과거 Claude 기록까지 128개 파일 한도에 넣었다. 실제 기록 사본에서 표시 기간 밖의 346개 파일을 제외하자 최근 20개 파일을 정상적으로 확인할 수 있었다.
- 한 번에 4MiB씩 읽는 도중의 대기 상태가 수집 실패와 같은 경고로 표시됐다. 이제 집계 중을 구분하며 새 로그가 쓰이지 않아도 남은 읽기를 이어간다. 화면이 닫혔을 때와 저전력 상태의 기존 지연은 유지한다.
- 토큰을 담지 않은 큰 도구 출력과 Claude의 `<synthetic>` 오류 안내까지 사용량 누락으로 취급했다. 큰 레코드는 최상위 종류를 확인해 사용량과 관계없는 종류만 제외한다. 사용량 레코드 자체가 크거나 종류를 확인할 수 없으면 누락 경고를 유지한다.
- 최신 Codex의 `token_usage_record`를 읽지 못하고 누적 `token_count`에만 의존했다. 요청별 기록이 있으면 이를 우선하고 누적 이벤트를 중복 합산하지 않는다. fork에 복사된 부모 기록은 제외하고, 자기 스레드의 명시된 요청만 포함한다. 구형 누적 기록도 계속 지원한다.

대시보드뿐 아니라 달력·프로젝트 집계에도 같은 요청별 기준을 적용했다. 기존 파생 캐시는 필요한 Codex 항목만 한 번 갱신하며 절감 기록과 원본 대화는 보존한다. 요청 식별자를 캐시에 기억해 복사·증분 읽기에서도 중복 집계를 막는다. 실제 읽기 실패·탐색/파일/이벤트 한도·구형 상속 기록 등은 도구별 상세 사유를 표시한다.

## 실제 기록과 독립 계산의 대조

검사 시점에 고정한 로컬 기록 사본에서 요청별 중복 제거와 날짜별 합산을 독립 계산했다. 같은 사본을 읽은 대시보드 수집기와 달력 집계기가 독립 계산과 일치했고, 제한된 읽기 패스가 완료된 뒤 수집 경고도 해소됐다.

실제 기록의 크기·요청 수·토큰 수·계산 상세는 로컬 전용 검증 자료에 보관한다. 이 검사는 해당 Mac의 로컬 기록에 대한 대조이며 계정 전체나 다른 클라우드 작업의 사용량을 보장하지 않는다.

## context는 쓸 만한가

함수·파일명과 구체적인 작업 목적을 주고 필요한 본문을 받는 용도로는 유용하다. 실제 stdio MCP에서 다음을 확인했다.

| 고정된 검사 | 결과 |
|---|---:|
| 기존 12개 질문: 핵심 파일 첫 순위·본문 포함 | 각각 12/12 유지 |
| 한국어만 사용한 4개 추가 질문: 핵심 파일 본문 포함 | 2/4 → 4/4 |
| 같은 한국어 질문: 핵심 파일이 처음 3개 안에 포함 | 1/4 → 2/4 |
| 200~250 추정 토큰의 다른 파일 보조 구현 보존 | 6/6 |
| 별도 작은 예산의 요청 본문·보조 구현 보존 | 4/4 |
| 본문 응답의 로컬 추정 예산 준수 | 모두 통과 |

한국어 사용량·수집·중복·전달·의존성 관련 표현을 보완했다. MCP 연결 시 AI에 사용 요령도 제공한다. 코드가 필요하면 `read_optimized` 한 번으로 시작하고, 파일 계획만 필요하면 `get_relevant_context`를 사용하도록 안내한다. 같은 질문에 두 도구를 습관적으로 연달아 호출할 필요가 없다. 변경 없는 본문 재사용과 compaction 후 `fresh`의 용도도 안내한다.

큰 파일의 좁은 구현 검사에서는 원문 4,665 추정 토큰을 본문 31 추정 토큰으로 전달했고, 같은 세션의 반복 요청은 본문 재전달 없이 12 추정 토큰이었다. 이는 해당 합성 입력의 텍스트 추정치이며 실제 모델 요금 절감률이 아니다.

넓은 자연어 질문의 첫 검색 결과가 항상 최적이라는 뜻은 아니다. 기존 12개 넓은 질문 중 5개는 8,000 예산으로 모든 필수 의존 구현이 들어가지 않아 경고했다. 이때는 표시된 보조 함수로 범위를 좁히거나 예산을 늘려야 한다. 위 수치는 코드 보존·검색 검사이며 AI의 수정 성공률·전체 언어 문법의 정확도를 증명하지 않는다.

## 검증과 반영

- macOS 전체 검사: **438개 통과**, 플랫폼 전용 3개 건너뜀. 마지막 검색어 보완 후 해당 검사 6개도 통과했다.
- 호환 준비 프로필: 15개 통과, 미지원 경로 5개 건너뜀.
- 실제 MCP의 예산 1·30·100·250·500, 중복 제거·fresh, 강제 인덱싱, 민감 경로·링크·프로젝트 경계, 잘못된 요청 후 복구 검사를 통과했다. 설치한 MCP에서도 재확인했다.
- 기존 서명 팀과 App Group·위젯을 유지한 빌드 2119를 `<local-app-bundle>`에 설치했다. 호스트·CLI·MCP·위젯 실행 파일 네 개가 검증 패키지와 일치하고 서명·doctor 검사가 통과했다.
- 실제 대시보드와 도구별 상세를 열어 경고 해소를 확인했다. 개인 정보 숨김 설정과 누적 절감 기록도 유지됐다.
- 직전 앱은 `<local-backup-app>`에 보존했다.
- 업데이트 전 통계 DB도 앱 지원 폴더 안의 비공개 백업에 보존했다. 사용량 본문이나 계정 백업 파일을 저장소의 검증 기록에 복사하지 않았다.

프로젝트의 `.codex/config.toml`이 존재하지 않는 이전 MCP 실행 파일을 가리키고 있어 설치된 앱의 경로로 복구했다. [Codex 설정 문서](https://learn.chatgpt.com/docs/config-file/config-basic)의 프로젝트 설정 우선순위와도 대조했다. 새 실행 파일의 실제 MCP 호출은 검증했다. **현재 진행 중인 Codex 채팅의 도구 목록은 Codex 재시작 후 갱신해야 한다.** Codex 앱 자체의 자동 제어가 차단되어 이 채팅의 연결을 직접 재시작하지 못했다.

합성 입력의 품질·회귀 결과는 [공개 검증 기록](benchmarks/usage-context-fix-20261023/), 요약은 [summary.json](benchmarks/usage-context-fix-20261023/summary.json)에 있다. 실제 사용량 대조·설치 원자료·실행 로그는 로컬 전용이며 저장소에서 제외한다. 대화 내용·자격 증명·요청 식별자도 공개하지 않는다. 공개 범위는 [검증 자료 안내](benchmarks/README.md)를 따른다.
