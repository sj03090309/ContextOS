# 달력 복원 및 기능 점검 · 2026-11-05

대상은 이 Mac에서 사용하는 메뉴바 앱, 달력·사용량·개발 시간, WidgetKit, Claude Code·Codex 연결, 로컬 MCP·CLI 및 소스 자동 반영이다. 기존 동작의 회귀를 고치고 검증했으며, 새로운 서버나 배포 체계를 필수 조건으로 추가하지 않았다.

## 달력 기록이 사라져 보인 원인

앞선 로그 수집 선택 도입에서 새 로그 읽기를 멈추는 동작과 저장된 달력 표시를 비우는 동작을 함께 처리했다. 설정이 기본 꺼짐인 설치본은 시작할 때 저장된 달력 집계를 읽지 않아 과거 기록이 모두 없어진 것처럼 보였다. 사용자 DB는 읽기 전용 백업 후 무결성과 기존 행 보존을 별도로 확인했다. 개인 날짜별 수치·질문·원본 로그는 이 문서나 저장소에 포함하지 않는다.

달력은 수집이 꺼져도 앱 DB에 이미 저장된 집계를 불러온다. 실시간 집계와 동일한 중복 제거 함수를 사용하며 원본 에이전트 로그를 다시 열지 않는다. 창 재열기·새로고침·일별 상세·빌드 로그도 저장된 기록을 사용할 수 있다. `저장된 기록 · 새 로그 집계 꺼짐`으로 새 집계와 구분하며, 수집 설정은 임의로 켜지 않는다.

이 점검은 수행한 범위의 회귀 검증이다. 기록은 저장된 집계를 표시하는 것이며 원본 로그가 삭제된 뒤 수집을 다시 켰을 때의 영구 보관소를 새로 만든 것은 아니다. 실행 중이던 MCP 프로세스는 재연결 후 새 코드를 사용하고, 위젯 갱신 시점은 macOS가 정한다. Windows 실제 실행과 고객 배포용 서명·공증은 이번 로컬 Mac 검증에 포함하지 않는다.
